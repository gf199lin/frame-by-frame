# P1.1 迁移说明：画像 Schema v1 → v2

## 1. 版本识别

- 顶层或 `profile_delta` 中 `schema_version === 2` → v2。
- 无 `schema_version` → 按 v1 读取，字段含义不变。
- `validate-run.mjs` 对 v1/v2 分别校验，旧 P0 JSON 不需重写。

## 2. 字段语义变化

| 字段 | v1 | v2 |
|---|---|---|
| `sample_size` | 证据条数 | **deprecated alias**，仍等于 `evidence_count` |
| `evidence_count` | 无 | 实际使用的有效证据数 |
| `independent_note_count` | 无 | 去重后的独立笔记数 |
| `duplicate_evidence_count` | 无 | 完全重复、被去除的证据数 |
| `duplicate_note_count` | 无 | 重复提交的笔记数 |
| `sufficient` | 无 | 独立笔记 >= 3、观察维度 >= 3、充分维度 >= 2 |
| `provisional` | 无 | `sufficient === false` 时为 true |
| `dimensions.*.status` | 无 | `observed` / `unobserved` |
| `dimensions.*.score` | 0–100 | observed 为 0–100；unobserved 为 `null` |
| `dimensions.*.lean` | high/low/balanced | unobserved 为 `unknown` |
| `dimensions.*.note_count` | 无 | 该维度覆盖的独立笔记数 |

## 3. 新增的输入字段

```json
{
  "note": "笔记原文",
  "film": { "id": "before-sunrise", "title": "Before Sunrise", "year": 1995 },
  "note_id": "sha256:...",
  "semantic_status": "relevant",
  "corrections_applied": []
}
```

- `note_id = sha256(namespacedIdentity + "|" + normalize(note))`。
- 身份优先级：`tmdb:<tmdbId>` → `film:<id>` → `title:<title>|<year>` → `identity_missing`。
- `tmdb:123` 与 `film:123` 属于不同 namespace，不会自动合并。
- `identity_missing` 使用 `recordId` 或本次输入的 `inputIndex` 生成运行内唯一 id；没有稳定记录 ID 时无法跨运行去重。
- `normalize` 只去空白、标点、零宽字符，不做语义改写。

## 4. 读取建议

- 旧代码只读 `sample_size` 时仍可工作，但应改用 `evidence_count`。
- 展示偏好时必须判断 `dimensions.*.status`：`unobserved` 不等于中性偏好。
- 判断画像是否可用时读取 `sufficient` / `provisional`，不要只看 `sample_size`。

## 5. 已知限制

1. 同义改写（如“结尾”与“结局”）不会被识别为同一 note_id，也不会被检索器召回。
2. 语义检查是保守规则，不是语义理解；`uncertain` 不等于无价值。
3. 跨笔记聚合要求调用方一次传入多个 `--evidence`；单次只传一个 draft 时 `independent_note_count` 最多为 1。
4. 旧 draft 缺 `note`/`film` 时只能得到 `identity_missing` 的运行内 id，无法跨运行去重。
5. 通用双字表是人工小表，不是语义模型；未覆盖的通用词仍可能产生弱命中。
6. 最高分并列时返回 `ambiguous=true`，top1 只是排序结果，不是唯一答案。
7. `identity_missing` 且没有稳定 `recordId` 时，重复提交无法被可靠识别。

## 6. P1.1.1 变化

### 6.1 检索降噪

- 新增 `GENERIC_BIGRAMS` 弱信号表（发生/出现/事情/时候/可能/觉得/这样/那样等）。
- 通用双字只按 0.25 计入正文权重，且**不计入有效双字**；即使出现在标题或标签，也不能单独使条目有效。
- 有效条件：至少 1 个非通用双字，且总分 >= 2。
- 输出新增 `effective_bigrams`、`ambiguous`、`tie_count`、`min_effective_bigrams`、`generic_bigram_weight`。
- `ambiguous=true` 表示最高分并列，调用方不得把 top1 当作唯一答案。

### 6.2 画像充分性

- `sufficient` 现在同时要求：独立笔记 >= 3、观察维度 >= 3、充分维度 >= 2。
- 新增 `sufficient_dimensions` 字段。
- 维度仍独立判断，允许部分维度 `unobserved` 或 `insufficient`，但整体可用至少需要 2 个充分维度。
- `validate-run.mjs` 在 v2 下强制该一致性；v1 路径不变。

### 6.3 电影身份

- `movieIdentity` 改为 namespace 形式。
- 缺失身份不再返回共用的 `|`，而是 `identity_missing`。
- `computeNoteId(film, note, { recordId?, inputIndex? })` 支持运行内区分。
- `profile.mjs` 新增 `identity_missing_count` 与 warning。
